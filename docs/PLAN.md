# BioVision — Development Plan

This document is the source of truth for *what gets built, in what order, and how we
know a phase is finished*. Every phase has a concrete artifact and a binary acceptance
criterion. A phase is not "done" because the code exists — it is done when the
criterion passes.

---

## 0. Repository layout decision

**Recommendation: a single repository (monorepo), not two.**

Rationale:

1. **The API contract is the product.** The response schema is defined in Python
   (Pydantic) and consumed in TypeScript. In one repo, a schema change and its frontend
   consumer land in the same commit, and CI can fail the pair together. Split repos make
   contract drift silent — the exact failure mode this project claims to prevent.
2. **The README is the deliverable.** This is a portfolio project shown to an executive.
   One URL that contains the architecture, the numbers, the code, and the demo link is
   worth more than two half-stories.
3. **Deployment is not coupled.** Vercel builds from a subdirectory (`frontend/`) with a
   root-directory setting; the VPS builds `backend/Dockerfile`. A monorepo costs nothing
   here.
4. **AGPL-3.0 already covers everything.** Since the whole work is AGPL anyway, there is
   no licensing reason to separate the frontend.

Deliberately **not** used: Turborepo/Nx/pnpm workspaces. Python and TypeScript do not
share a package manager, so a monorepo tool would add configuration without removing
any. Two independent toolchains in two directories is simpler and reads better.

Split into two repos only if the frontend later needs a non-AGPL license or a separate
contributor set. Neither applies now.

## 2. Phases

Each phase ends with a summary to the project owner and a README update.

### Phase 0 — Repository and guardrails ✅ **done**
**Built:** repo init, `.gitignore` + `.env.example` first, `uv` project, `ruff` + strict
`mypy` + `pytest`, AGPL-3.0 `LICENSE` and `NOTICE.md`, GitHub Actions CI, Dockerfile,
compose files, Caddyfile.
**Acceptance met:** `ruff check` clean, `mypy` clean under `strict` across 50 files,
71 tests passing, CI fails if a `.env` is ever tracked.

### Phase 1 — Contract-first API skeleton ✅ **done**
**Built:** the full response contract in pydantic with the honesty rules as model
validators; all four endpoints; model `Protocol`s plus deterministic mocks; `lifespan`
loading; one error envelope; `docs/openapi.json` exported and drift-tested.
**Acceptance met:** `POST /v1/analyze` returns a schema-valid response from mocks;
`/health` reports per-model state; the app boots with zero weights on disk; contract
tests cover both response branches and every documented status code.
**Why first:** the contract is what the frontend and every later phase depend on. Getting
it wrong later is expensive; getting it wrong now costs nothing.

### Phase 2 — Image ingestion pipeline
**Build:** all 8 pre-inference steps, in the fixed order, in `orchestrator.py`.
**Acceptance:** unit tests for every rejection path (oversize → 413, unsupported → 415,
animated GIF, <200 px, corrupt bytes); HEIC decodes; EXIF orientation is applied
(verified by pixel comparison); pHash is stable across re-encoding and differs across
distinct images; the stored derivative contains no EXIF; the blur test on a fixture with a
visible face and plate reports non-zero counts.

### Phase 3 — Gate and Router
**Build:** CLIP/SigLIP wrapper, `domains.yaml`, thresholds in config, gate + router wired
into the orchestrator.
**Acceptance:** end-to-end analysis with real models on CPU; a selfie returns `422`; a
test adds a fake domain to `domains.yaml` and asserts `/v1/domains` reflects it **with no
code change** — this test is the architectural promise, in executable form.

### Phase 4 — Evaluation and calibration of the router
**Build:** router eval set (~50 images/domain), calibration split, `eval_router.py`,
`calibrate_router.py`, reliability diagram, ECE, threshold selection.
**Acceptance:** confusion matrix and before/after ECE committed and pasted into the
README; `temperature.json` committed; a response is `calibrated: true` **only** when that
file loaded successfully; a regression test asserts ECE does not exceed the recorded value.

### Phase 5 — Vehicle specialist
**Build:** CarDD YOLO-seg loading, mask → `findings` mapping, `area_ratio`, the severity
heuristic (documented explicitly as a heuristic, not a calibrated output),
`eval_specialist.py`.
**Acceptance:** per-class mAP table in the README including the weak classes; the 20-image
golden set passes; specialist latency measured on CPU.

### Phase 6 — VLM fallback and cost control
**Build:** VLM client, pHash cache, per-user daily limit, global monthly budget counter,
graceful degradation.
**Acceptance:** submitting the same image twice issues exactly **one** upstream API call
(asserted by a mocked client call count); exhausting the budget returns
`503 service_degraded` while the vehicle path still returns `200`; measured cost per
request written into `docs/COST.md` and the README.

### Phase 7 — Supabase: auth, persistence, storage
**Build:** schema migrations, RLS policies, Google OAuth, Storage bucket, `/v1/requests`,
retention policy.
**Acceptance:** an RLS test proves user A cannot read user B's rows *through the API and
through a direct client*; stored objects are verified blurred + EXIF-free + ≤1280 px;
`/v1/requests` returns only the caller's history.

### Phase 8 — Frontend
**Build:** upload flow, result view with mask overlay, history page, Google sign-in, and —
importantly — a distinct visual treatment for the uncalibrated / no-specialist state.
**Acceptance:** works on mobile viewport; a `building` upload visibly communicates "no
expert model for this domain" without the user reading JSON; error codes render as human
sentences; no API key reaches the browser bundle.

### Phase 9 — Deployment
**Build:** production Dockerfile (CPU torch), `docker-compose.prod.yml` with **2 workers
max** and memory limits, Caddy with automatic TLS, Vercel project, DNS.
**Acceptance:** both domains live over HTTPS; `/health` green from the public internet;
`bench_latency.py` run **on the VPS** and its p50/p95 table pasted into the README; the
container survives a reboot.

### Phase 10 — Demo readiness
**Build:** architecture diagram, filled README tables, an explicit failure gallery, a
90-second demo script (vehicle photo → structured findings; building photo → honest
`null`; selfie → `422`).
**Acceptance:** a reader unfamiliar with the project can state what it does, what it
cannot do, and how well it does it — in under five minutes, from the README alone.

## 3. Sprint log

### Sprint 1 — Phases 0 + 1 ✅ **complete**

Delivered: repo scaffolding and guardrails; the complete API contract with the honesty
rules enforced as pydantic validators; all four endpoints; model protocols and
deterministic mocks; the domain catalogue; one error envelope covering every documented
status; 71 tests; committed and drift-tested OpenAPI document; Docker, compose, Caddy
and CI.

Two decisions came out of the implementation rather than the plan — see
[`DECISIONS.md`](DECISIONS.md) ADR-010 (splitting `calibrated` into two fields) and
ADR-012 (specialist names must exist in code).

### Sprint 2 — Phase 2, the ingestion pipeline

**Scope:** the eight pre-inference steps, for real.

1. Add `Pillow`, `pillow-heif`, `imagehash`, `opencv-python-headless`.
2. Decode and verify; replace the byte-sniffing animation check with Pillow's
   `n_frames`; enforce `min_image_dimension`.
3. EXIF: read capture time, GPS *presence*, device; apply orientation before any model
   sees the image; strip on output.
4. pHash, and a test that it survives re-encoding but separates distinct images.
5. Face and plate redaction, with the miss rate measured and published (ADR-006).
6. Strip + resize to 1280 px long edge; this derivative is the only thing ever stored.
7. Replace the synthetic byte fixtures in `conftest.py` with genuinely decodable images,
   including a real HEIC sample.

**Definition of done:** every rejection path has a test (oversize, unsupported, animated,
under 200 px, corrupt); a HEIC iPhone photo round-trips; the stored derivative provably
carries no EXIF; `Privacy` reports real detector names and counts; the p50/p95 table gains
a measured `preprocess` row.

**Explicitly out:** real CLIP (Phase 3), YOLO (Phase 5), Supabase (Phase 7), VLM
(Phase 6), frontend (Phase 8).
